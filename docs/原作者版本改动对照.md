# 白龙桌宠 v0.5.1 改动对照（供原作者参考）

本文只比较原作者公开版本与本次拟反哺的代码、素材和构建改动。按最终保留的实现整理，不记录中间尝试和撤回过程，也不将原作已有能力算作新增功能。

- **作者基线：** [v0.5.1，提交 b102e73](https://github.com/jingh12312-rgb/bailong-desktop-pet/tree/b102e734f20bb50889af12df5778f1499109f41b)。
- **改动快照：** 本仓库 `cb66eba`，另含本次 macOS 全屏窗口行为修订，代码标记 `0.5.1-opt.23`，整理日期 2026-11-08。`opt` 后缀用于标识这批改动，不代表作者已经采纳或发布。
- **比较依据：** 直接对照上述提交的源码与当前实现；更新记录作为补充。本文不声称覆盖作者此后发布的版本。

## 一、沿用原作的能力

角色与动画创作、35 段动作体系、拖动与落地、自移动、吸边探头、桌宠大小设置、额度查询、内置 Codex 对话、历史记录、外部任务观察、任务完成提醒、气泡详情及全屏自动隐藏入口，均已有原作基础。

透明 WebM 通过 **FFmpeg / libvpx-vp9 输出 RGBA** 也是原作者已有的播放方案。本次沿用该方案，没有另造解码框架，也没有将这些基础能力列为新增功能。

依据：[原版 README](https://github.com/jingh12312-rgb/bailong-desktop-pet/blob/b102e734f20bb50889af12df5778f1499109f41b/README.md)、[原版 pet.py](https://github.com/jingh12312-rgb/bailong-desktop-pet/blob/b102e734f20bb50889af12df5778f1499109f41b/app/pet.py)。

## 二、新增功能与性能调整

| 项目 | 作者 v0.5.1 | 本次改动 |
| --- | --- | --- |
| 动画加载 | 启动时逐段解码全部动作，放入 `pinned_frames` 长期保留 | 后台按当前动作解码，默认只预读有限帧；切换动作取消旧解码，隐藏暂停预读，退出回收线程与解码进程 |
| 开始播放的时机 | 启动阶段先完成全部动作预加载 | 默认在首批画面可用后播放，后续帧随播放补充；整段预加载模式仍需等待当前动作加载完成 |
| 性能设置 | 没有独立的性能设置窗口 | 新增画质、帧率、预加载帧数和当前动作整段预加载开关；即时保存、生效，无“应用”按钮 |
| 画质与帧率 | 没有供用户选择的上述性能档位 | 默认 512×512、素材原帧率、12 帧缓冲；最高 720×720，另有 384、256 和跟随屏幕；帧率可选满帧、20、15 FPS |
| 缓冲控制 | 全动作预加载，没有面向用户的缓冲上限设置 | 缓冲可设 6～240 帧；输入框与滑条同步；整段预加载默认关闭，开启时只针对当前动作 |
| 性能统计 | 没有独立的性能统计界面 | 新增 FPS、帧缓冲、主进程与 FFmpeg 的 CPU／运行内存、播放状态、硬件及版本、连接与任务信息 |
| 内存统计口径 | 没有对应统计面板 | 将主进程和 FFmpeg 分项展示；两者的 RAM 合计不包含 Codex 及其工具进程，也不重复加上帧缓存估算 |
| 平台资源指标 | 没有对应统计面板 | Windows 显示主进程私有提交量；macOS 显示物理占用与累计 Swap 换入；Linux 显示 RSS 与当前 VmSwap，不把不同指标混称为磁盘写入量 |
| 硬件与连接信息 | 没有汇总展示入口 | 按需查询 CPU／GPU 型号、桌面端和内置 CLI 的 PID／路径／状态；候选路径与已运行进程分开显示 |
| 统计窗口操作 | 无该窗口 | 双栏布局，窄窗口改为上下排列；长字段悬停显示全文，提供“复制信息”。各平台均不设分组“详情”按钮；任务气泡的“详情”保留 |

这些改动减少了默认常驻动画帧的范围，但本文不据此给出整机 RAM 或启动时间的降幅；这类数字需要同机、同设置的原版对照测量。

## 三、对话、任务提醒与气泡修复

| 问题／原版行为 | 本次改动 | 适用范围 |
| --- | --- | --- |
| 临时聊天默认选中最新记录，最新记录若来自 Codex 同步，发送会尝试写入外部会话 | 默认选择最近的桌宠自有会话；外部同步记录保持只读，发送前阻止误写，并提供“转到 Codex”入口 | 共用逻辑 |
| 从外部同步记录创建新对话会沿用该记录的目录 | 使用桌宠配置的默认任务目录创建自有对话 | 共用逻辑 |
| 工具进度与对话内容混在一起，命令输出能进入历史事件 | 统一显示临时工具状态，截断长内容；工具输出、参数及私密推理不投影为聊天消息 | 共用逻辑 |
| 外部任务的单个工具失败会形成持续告警，即使整轮任务仍在执行 | 将单次调用失败作为本次工具状态展示；任务整体失败、权限确认和用户提问继续分别处理 | 共用逻辑 |
| 任务气泡正文按固定高度预留，短结果或长内容变短后留下空白 | 按实际文字宽度和文档高度计算正文区域；达到高度上限后滚动；内容变化时重新计算并收回空白 | 共用逻辑 |
| 连续互动换文案时，布局尚未更新就取高度，出现文字裁切 | 先显示新控件并刷新布局，再计算气泡高度 | 共用逻辑 |
| 对话界面使用固定像素字号与固定输入框尺寸 | Windows 保留原作字体选择，macOS／Linux 使用系统字体；尺寸参照字体度量与 Qt 缩放 | 共用逻辑，按平台选字体 |
| 角色周围出现系统窗口阴影 | 在角色窗口明确设置关闭系统阴影的窗口标志 | 共用窗口配置 |

实现位置：[对话界面](../app/chat_ui.py)、[对话事件](../app/chat_backend.py)、[外部任务观察](../app/desktop_task_sync.py)、[临时工具进度](../app/task_activity.py)、[气泡与桌宠窗口](../app/pet.py)。

## 四、平台适配修复

### macOS

| 作者版本中的情况 | 本次改动 |
| --- | --- |
| Qt 工具窗口已有 `MoveToActiveSpace` 时，再加入 `CanJoinAllSpaces` 会触发 AppKit 互斥标志异常 | 加入跨空间标志前先移除冲突标志，保留其他窗口行为 |
| 工具窗口随应用失焦隐藏，临时聊天未完整应用桌宠的窗口配置 | 关闭失焦隐藏，设置合适的浮动层级，并将同一平台配置应用于临时聊天 |
| 默认历史目录与本机已有的旧 Python 移植版相同，但历史格式不同 | 使用独立的 `BailongPetOriginal` 数据目录，避免覆盖旧数据；显式数据目录配置继续有效 |
| 优先找到 PATH 中的独立 Codex CLI，桌面端内置版本排在后面 | 在显式配置之后，优先查找桌面应用内置 CLI；聊天与额度查询共用查找逻辑 |
| 桌宠等工具窗口设置为 FullScreenAuxiliary，可以跟入全屏空间 | 改为 FullScreenNone，桌宠、气泡及临时输入窗不参与全屏空间，同时保留普通桌面间的共享 |
| 全屏检测遇到前台应用的首个普通窗口就返回，小窗口会阻断后续判断 | 遍历全部前台普通窗口，按完整屏幕 frame 检查覆盖；保留隐藏／恢复延迟 |
| 输入框提示沿用 Ctrl+Enter | 提示改为 Command+Enter，实际按键继续采用 Qt 原生映射 |

**“填充”与“全屏”是不同状态。** 当前采用用户指定原生工程中的两层实现：窗口自身通过 `FullScreenNone` 不参与全屏空间；辅助检测使用完整屏幕边界，不扣刘海安全区，也不使用填充对应的 `visibleFrame`。不再使用上一轮的 `currentSystemPresentationOptions` 判定。参考源码为原生工程 `249d82b` 的 `Pet.swift` 窗口初始化与 `checkDesktop()`、`Bubble.swift` 和 `ChatComposer.swift`；仅按需移植窗口行为，未修改原生工程。填充、进入全屏和退出全屏仍待 Qt 构建的实机验收。

实现位置：[macOS 窗口与数据路径](../app/platform_support.py)、[CLI 查找](../app/quota.py)、[对话输入](../app/chat_ui.py)。Windows 的原有全屏检测未修改。

### Linux

| 作者版本中的情况 | 本次改动 |
| --- | --- |
| 没有 Debian、Fedora、Arch 对应的完整构建入口 | 增加三类构建脚本、系统依赖安装选项和 X11／XWayland 启动脚本 |
| 桌面会话选择与输入法接入缺少相应处理 | 打包启动默认采用 XCB／XWayland；接入 IBus 输入上下文，保留显式环境配置 |
| 非 macOS 的运行状态默认写入程序目录 | Linux 改用用户 XDG 数据目录，允许安装目录只读 |
| 音效分支未接通 Linux 播放 | 使用系统 `paplay` 播放短音效，并从 Linux 包中移除 QtMultimedia 依赖 |
| 从图形桌面启动时，终端 PATH 中的 CLI 不一定可用 | 增加桌面应用内置 CLI 和常用安装路径查找 |
| 小型设置窗口缺少针对 Linux 的窗口按钮配置 | 性能与相关设置窗口保留最小化、关闭，移除最大化；历史窗口沿用原有配置 |

Linux 保留构建和适配工作，**尚未接入 Linux 全屏自动隐藏**；不能将 Windows／macOS 的检测能力写成 Linux 已支持。Fedora 用户反馈仍需在对应环境继续验收。

实现位置：[Linux 启动与音效](../app/pet.py)、[平台数据目录](../app/platform_support.py)、[窗口配置](../app/performance_ui.py)、[Linux 构建](../work/build_linux.sh)。

## 五、构建、分发与素材

| 项目 | 作者 v0.5.1 | 本次改动 |
| --- | --- | --- |
| Windows 构建 | 手动安装依赖，执行原 Windows 构建、发行脚本 | 保留原入口，新增 PowerShell 5.1／7+ 自动化入口，选择解释器、按需补依赖、生成完整目录包及 ZIP |
| macOS 构建 | 作者 README 明确注明尚需补齐 FFmpeg 打包，未完成 Mac 实机验收 | 补齐素材、解码器、依赖许可、应用图标和本地签名；默认自动编译并复用本机架构的精简 FFmpeg |
| 解码器 | Windows 完整包携带通用 FFmpeg | 提供固定源码版本的精简解码器，保留 WebM／VP9 Alpha、缩放、帧率调整和 RGBA 输出；避免同一解码器重复打包 |
| 运行库整理 | 原发行流程收集完整运行依赖 | Windows／Linux 按平台排除未使用插件；Windows 保留 QtMultimedia，Linux 使用系统音效方案；保留所需输入法和桌面组件 |
| 素材准备 | 从作者完整 Windows 发布包手动复制 `outputs` 与 `tools` | 所有构建入口共用素材准备脚本，缺少素材或清单需切换时自动下载；显示已下载／总大小、百分比和实时网速 |
| 平台产物 | 主要提供 Windows 包，附 macOS 构建源码 | 增加 macOS、Debian、Fedora、Arch 的构建与归档入口；Fedora 可生成 RPM；产物按平台和架构放入 `dist-*` |
| 自动发布 | 没有本次新增的五平台工作流 | 新增 Windows、macOS arm64 和三类 Linux 的 Actions 构建流程，支持复用已有构建产物发布 |
| 动画素材 | 作者提供的 35 段透明 WebM | 采用用户选定的 idle、idle2、drag、landing 四段 Alpha 修复结果，其余 31 段保留作者原文件；四段以 720×720、24 FPS 的透明 WebM 分发，保留原时长及渲染参数 |
| 应用图标 | 没有本次修复首帧对应的统一构建图标 | Windows EXE 与 macOS App 使用修复 idle 第一帧，构建时导出 ICO／ICNS；角色创作与素材归属仍为原作者 |
| 发布校验流程 | 原发行脚本生成源码及压缩包 SHA-256 | 当前默认发布流程取消 SHA-256 生成与附件；保留必要的缺失依赖、素材路径和构建失败报错 |

四段修复素材使用 VP9 Alpha、CRF 18 的高质量有损编码；保持 720×720 不等于与修复 PNG 逐像素无损一致。原素材和修复源文件保留，修复方法、素材归属见 [素材说明](../ASSETS.md) 与 [修复素材说明](修复素材备选包.md)。
